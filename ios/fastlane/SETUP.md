# Shipping TotoApp: the automated path

This replaces the manual "Product → Archive → click through Xcode"
flow in `../DEPLOY_IOS.md` for day-to-day builds. Read that file first
for the one-time Apple Developer account setup; this file is what you
run afterward, every time you want to ship a build.

(`fastlane/README.md` in this folder is auto-generated by fastlane
itself and gets overwritten every run — this file won't be.)

Nothing here authenticates with your Apple ID + password/2FA. Every
lane uses an **App Store Connect API key** instead — that's what makes
this scriptable. The key, and the passphrase that protects the signing
certs, live in **1Password**, never in this repo.

## One-time setup (do this once, on each Mac you'll ship from)

1. Install fastlane: `brew install fastlane` (this repo also has a
   `Gemfile`, so `bundle exec fastlane ...` works too if you prefer
   pinned versions — either is fine).
2. Install the 1Password CLI: `brew install 1password-cli`, then in the
   1Password desktop app: **Settings → Developer → Integrate with
   1Password CLI** (turn it on). With that on, `op` commands unlock via
   Touch ID / the already-unlocked app — no separate `op signin` typing
   your master password every time.
3. In 1Password, create a vault (e.g. "TotoApp Deploy") with these
   items:
   - **App Store Connect API Key** — an item with fields `key_id`,
     `issuer_id`, and the `.p8` file itself attached as a document.
   - **match passphrase** — a password item holding the passphrase
     `match` uses to encrypt/decrypt the certs repo
     (`chintheman/toto-ios-certs`). Generate a strong random one; you
     never need to remember it, 1Password holds it.
4. Copy `fastlane/.env.op.example` to `fastlane/.env.op` (already
   gitignored) and fill in the `op://` references to match your actual
   vault/item names.
5. **Bootstrap signing certs (only ever needed once per Apple Developer
   account, not once per machine):** if `chintheman/toto-ios-certs` is
   still empty, run:
   ```
   op run --env-file=fastlane/.env.op -- bundle exec fastlane certs_bootstrap
   ```
   This is the one step Apple requires an interactive login for the
   very first time. After this, every other machine just reads the
   encrypted certs — see step 6.
6. On every other/new machine, sanity-check signing works:
   ```
   op run --env-file=fastlane/.env.op -- bundle exec fastlane test
   ```

## Everyday use

**Ship a new TestFlight build:**
```
op run --env-file=fastlane/.env.op -- bundle exec fastlane beta
```
Bumps the build number, archives, uploads to TestFlight. Does **not**
submit for App Review — go test it on your phone via TestFlight first.

**Seed or refresh the local metadata files from what's actually live:**
```
op run --env-file=fastlane/.env.op -- bundle exec fastlane pull_metadata
```

**Push edited App Store listing copy/screenshots** (no binary, no
submission):
```
op run --env-file=fastlane/.env.op -- bundle exec fastlane metadata
```

**Submit the TestFlight build you already approved for App Review:**
```
op run --env-file=fastlane/.env.op -- bundle exec fastlane release
```
`automatic_release` is deliberately off — once Apple approves, you
press "Release This Version" in App Store Connect yourself.

## Why this is safe to run unattended-ish

- No Apple ID/password/2FA anywhere in this flow — API key only.
- `match` runs `readonly: true` on every lane except `certs_bootstrap`,
  so a normal `beta` run can never silently regenerate/invalidate a
  cert another machine depends on.
- The certs repo (`toto-ios-certs`) is encrypted at rest — its GitHub
  privacy setting isn't actually the security boundary, the 1Password-
  held passphrase is.
- Nothing here auto-submits to App Review. `release` requires you to
  run it by hand, after you've personally tested the TestFlight build.
